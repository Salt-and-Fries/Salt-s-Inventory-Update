# Focused native Cinder Shop checks

Use `prepare.py` with the original audited `pr-base-shop.json` fixture, current
Core 0.1.6 and Compatibility 0.1.3 jars, `--side integrated`, and a fresh run ID.
The wrapper extends the excluded forge observer with read-only native offer,
component, portrait, inventory and registered-handler observations. Its pointer
input matches the native render-time hover behavior before ordinary clicks.

The fixture adds the original parent `past/treasurer.json` definition byte-for-
byte in a code-free data jar, with original audited item providers. The native
End advancement is granted through an operator command to unlock the original
Sell offers. No offers, subject binaries or UI assets are modified. The real
Serkonid opens through `interactAt` via a player entity ray within normal reach.

Run `check.py <run-directory>` once the generated client publishes `ready.json`.
It performs 24 focused assertions on this screen: native initial state, dragging,
payment refusal, one successful original transaction in each category, Cinders
preservation, tabs, scrolling, displayed/native offer consistency, live GUI
scale and position changes, separate Inventory, closing, native handler cleanup,
reopening and eight-block reach. Operator commands seed disposable progression
and materials; menu actions use normal screen input.

Client item previews can acquire an empty NBT tag while rendering; the offer
comparison ignores only that empty tag, while comparing the remaining native
offer data. Scroll verification observes actual offer-row movement rather than
assuming a library getter exists.

Timed restocking, finite-stock exhaustion, special prices, every merchant and
dedicated-server multiplayer are outside the focused coverage. This does not
run a complete functional/gameplay suite. Forge builds check optional-mod
compilation/isolation only; the audited embedded Base release is Fabric.
