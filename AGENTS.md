# Testing preferences

- For ordinary changes, test only the menus, controls, and features affected by the change. Use focused checks appropriate to its scope.
- Do not run the complete functional or gameplay suite after each change. Run a complete functional suite only when the user explicitly requests it.
- Report which focused checks ran and any relevant coverage limits. Do not describe focused checks as a complete functional test.

# UI design guidance

- For SIU window mockups and compatibility UI work, read [the window design philosophy](docs/markdown/siu-window-design-philosophy.md). It records the native-artwork, layout, clipping, attachment and verification principles refined during Project Everything. Follow the user's current instructions and approved designs when they differ from its examples.
