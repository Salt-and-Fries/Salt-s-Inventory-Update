# Native container view and top dropdown

The feature supports Fabric and Forge on 1.20.1, and Fabric and NeoForge on 1.21.1, 1.21.11, 26.1.2, 26.2 and 26.3.

- Hold Shift (or the rebound modifier binding) over a container's close control: its icon and tooltip become **Maximize**. Click to show the original container screen, including its player inventory, with the other SIU windows out of view.
- The top-center screen edge exposes a 96 × 32 pixel tab on hover. It says **Close All** on the desktop and **Return** in native view.
- **Show Top Dropdown** in the config menu (default On; JSON `showTopDropdown`) can hide the desktop tab entirely, including its hover/click area. Holding Inventory still reveals Close All. Maximized views retain their Return tab regardless of this preference.
- Click Return, or tap the configured Inventory binding, to restore the same desktop windows, geometry and cursor. Mouse bindings also work.
- Hold Inventory in either view to reveal **Close All** and its wrapping progress line. The existing configured hold duration and quarter-duration progress delay remain in use. Releasing after completion does not reopen the workspace.
- Close All closes the workspace even with Persistent Windows enabled. Esc on the ordinary desktop retains its existing persistent hide behavior. Native text fields retain the Inventory key for typing while focused.

The native view uses the original screen class and the existing live menu. SIU's authenticated session transport and shared cursor remain active. This bypasses the window presentation while retaining item-source checks and session ownership; it does not disable server-side compatibility code. No public API or network payload changes were needed.

Changing presentation must not call `menu.removed()` on the client: that would clear crafting inputs. Native widget save callbacks can still use their registered authenticated payload handlers during the return transition.

The tab and control sheet live in `artwork/shared-resources/core/assets/salts_inventory_update/textures/gui/`. Core and AE2 management controls use `window_controls_native_view.png` on every target.

## Focused verification

The repeatable game check is:

```powershell
python tools/run-native-view-qa.py --minecraft 1.20.1 --loader forge --run unique-lowercase-run-id
python tools/run-native-view-qa.py --minecraft 26.3 --loader neoforge --run another-unique-run-id
python tools/run-native-view-matrix-qa.py --run unique-matrix-run-id
```

These runners use disposable worlds and built Core JARs. Find reports and screenshots under `build/window-controls/gameplay/<minecraft>-<loader>-<run>/` and launcher summaries under `output/native-view/<run>/` or `output/native-view-all-targets/<run>/`. Pass `--targets` to run selected pairs or `--build-compatibility` to build the six native AE2 adapters before the Core checks. The test fixture supplies synthetic Shift through each release's input API.

Coverage includes the Maximize sprite and tooltip, clicking the actual title control, native chest pickup and quick move, switching with a carried stack, window identity and geometry preservation, Return and Close All tab clicks, Inventory tap/hold, rebound keyboard and mouse Inventory bindings, original player inventory and periodic packets, retaining crafting inputs through native close, and native anvil renaming. Dropdown checks cover preference persistence, removal of the hidden hover/click area, Inventory-hold access and Return access with the setting disabled.

Focused unit tests cover tab activation, hover/retraction, forced opening, resize centering, clock discontinuities and the visibility exceptions. `TopDropdownConfigTest` also covers migration of existing configs, saving the disabled preference and resetting defaults. Run with:

```powershell
./gradlew.bat -I versions/26.3/sort-tests.gradle :26.3:fabric:test --tests '*DesktopTabStateTest' --tests '*TopDropdownConfigTest'
```

These are focused checks, not a complete gameplay or all-mod qualification campaign. Custom mod screens and every GUI scale have not each been exercised by this feature-specific run.

Verified on 2026-11-10: `native-view-fabric-05` and `native-view-neo-04` each completed with 95 report records and zero failures. All four tab unit tests passed. Each new JAR retains byte-identical copies of the previous build's 155 public API classes and 46 network classes. The extended sheet also preserves every pixel of the original twelve control columns.

The new build copies, combined verification record and previews are in `output/native-view/`. The previously qualified `dist/core/` JARs have been preserved; the native-view build copies have a `-native-view.jar` filename suffix.

## Maximized player-inventory sync crash

A periodic SIU mode packet exposed an incorrect assumption in the native payload hook: the player's inventory has no registered `MenuType`, and its `getType()` throws `UnsupportedOperationException`. Custom payload and rename handler lookups now skip menus without a registered type. Ordinary packets continue through their original transport; registered containers retain their existing handler keys.

The initial smoke test returned from the player inventory before that periodic send. Its regression now forces a send while the inventory is maximized, keeps that view open for at least six seconds to observe another natural send, then verifies Return and cleanup. Run this focused case with `tools/run-native-view-qa.py --loader fabric --run <unique-id> --player-inventory-only` (or `--loader neoforge`).

Verified on 2026-11-10: `inventory-sync-fabric-01` and `inventory-sync-neo-01` each passed with 17 report records and no failures. Three `NativeMenuTypeTest` unit tests cover unregistered menus, registered menu identity and unrelated errors. This is a focused crash regression, not a rerun of the complete gameplay suite. Fixed build copies and their verification record are in `output/native-view/player-inventory-fix-01/`.
