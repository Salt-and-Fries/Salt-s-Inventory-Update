# Reusing unaffected publisher results

The original campaign has 62 clean latest profiles out of the full 65-profile
plan. One latest profile failed and two partition profiles were not executed.
The failed 26.3 NeoForge profile subsequently passed its build14 replay. Fresh
replay counts must be reported separately from the original results.

The initial build14 transition described in this section changed only the
Traveler packet callback/state classes and Mixin minimum-version declarations
in Compatibility. At that transition, all twelve Core and twelve Controlify
archives were byte-identical to build13. This statement concerns those exact
archived pairs; it does not describe every later candidate called build14.
Replaying an unaffected profile solely to change its generation label would
not test changed behavior.

Later qualification found and repaired separate text/publication, native film,
Create, Mine Cells, Extended AE and MI issues. Their exact transitions and native
follow-ups are in the [nine-edge repair-chain record](../../output/release-readiness/repair-prefix-equivalence-483-01.json).
The strict consumer rechecks those particular edges and the original test
scope before retaining evidence. Newer failed attempts cannot inherit an older
pass. The separately prepared final logger, book-texture and REI corrections
also require their own normal build, exact compiled-delta inspection and native
checks; this initial retention record cannot qualify them by itself.

The narrowly scoped retention tools require all of the following:

- Original clean completion, exact assertion/case counts, unchanged measured
  QA/generator inputs and preserved actual runtime observer binaries.
- Exact old/current archive pairs, with no additional payload changes.
- No native Traveler class or mod identity in any active runtime jar, including
  loader-declared nested dependencies. Traveler-present profiles require replay.
- Actual runtime Mixin engine identity, accepting native version comparisons,
  boundary/too-old controls and unchanged nonminimum configuration content.
- Unchanged Traveler absence guards, initialization and state semantics. The
  legacy native-target pseudo mixin remains inactive when its target is absent;
  modern connection hooks retain the identical send method, which declines
  packets outside an active Traveler widget input scope.
- A separately archived historical record retaining its **original subjects**.
  An explicit equivalence links that scope to the current candidate. It is never
  represented as another gameplay execution or additional assertions.
- No newer failed, running, interrupted or otherwise unknown attempt superseded
  by the old result. A real clean current-artifact replay takes precedence.

The original 65-job plan, every failed attempt, both unexecuted partitions,
entry-only limitations and specialized coverage gaps remain visible. Retention
does not establish new native features, a complete gameplay pass, final server
qualification or release approval. The final independent review remains required.

Production profiles did not fingerprint their generated Java separately. Their
exact executed observer jars and original measured generator inputs are retained.
Only generated inputs actually fingerprinted by an original run are labeled as
measured generated-source evidence; no retrospective execution hash is invented.

The policy and archive corruption checks are focused offline validation. The
runtime version-comparison probes execute real native classes in isolated JVMs,
but do not launch Minecraft or qualify menus.

## Separate final Core corrections

The prepared build14-to-build15 transition changes the detailed-render
logger's format and two constant arguments on all twelve Core targets, plus
one known enchanting-book texture identifier on the two 1.21.11 targets.
The latter fixes an observed missing native resource and black book rectangle.
It has its own stricter gate:
`python tools/reconcile-core-log-evidence-transition.py --id final-01`.
`--plan-only` lists prerequisites and grants no equivalence.

The gate requires the completed normal build and immutable source snapshots,
exactly six reviewed source files, all twelve real detailed-render smoke
receipts and loaded-code checks, both actual 1.21.11 book resource/render/reload
workflows, and a newly compiled ASM inspector that rechecks every actual
old/new archive pair. Ten Core archives may contain only the logger change;
the two 1.21.11 Core archives may additionally change exactly the specified
book-field initializer literal. The additional inspector retains the original
logger-only mode and rejects unrelated members, instructions and resources.
All twenty-four Compatibility/Controlify archives must remain byte-identical.
Later uncompiled production changes invalidate the link.
The original build14 jars remain preserved alongside their original results.

This gate is prepared, not yet passed. Its certificate alone assigns no
publisher or feature coverage. Report integration must retain original
subjects and QA/runtime archives, validate every original assertion and native
publisher, honor newer failures/live attempts, and label the explicit
scoped final-Core equivalence. The earlier build13-to-build14 Traveler/Mixin
policy must still be verified independently where it applies. Neither policy
creates another execution, increases assertion counts, closes missing feature
coverage, or substitutes for the final independent review.

The final report consumer is implemented but remains unqualified until those
real gates finish. After the actual certificate, final JUnit archive and all
registered native queues are complete, the report commands are:

```text
python tools/build-release-coverage-backlog.py --generation build15
python tools/collect-release-qualification.py --generation build15
```

The consumer independently reruns the strict source/archive/smoke verification
with another fresh ASM compilation. It retains original subject hashes and
records explicit old/new bindings. Current-generation proofs take precedence;
old build14 proof filenames and hashes stay unchanged. An old Core `dist`
reference may resolve only to the certificate's exact preserved build14 bytes,
and the report records both the original reference and physical locator.
The earlier Traveler equivalence is verified separately against its original
build14 subjects and then linked to the final-Core certificate. A current failure
or live workflow cannot inherit an old pass; failed native queue entries need
an explicit matching resolution and evidence. Modern Powah's actual final15
executions remain fresh final15 evidence. Read-only feature records receive
the same evidence-reference checks as mutable inventory records. The original
logger-only schema remains separate; only the explicit combined-fix schema
can accept the two book initializer changes, and it requires both actual
book workflows before any retained final-Core binding can be issued.

The measured native publisher coordinator and its retention helper remain
frozen. Final-report preserved-artifact lookup lives separately in
`tools/focused_release_evidence_publisher_final_core.py`; the build14 path
delegates to the original helper unchanged. The adapter retains the same
verification policy and does not approve a certificate or native execution.
The 26.2 NeoForge c0 a2 game process passed, but its outer attempt failed when
this reporting helper was edited during execution. That failed input guard
remains recorded; restoring the helper does not relabel the attempt a pass.
All previously completed profiles retain their original measured inputs.
