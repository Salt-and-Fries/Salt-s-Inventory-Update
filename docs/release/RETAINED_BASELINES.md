# Retained feature baselines and candidate equivalence

An old successful test does not qualify a rebuilt jar solely because its
filename or version is unchanged. This record identifies exact retained
runtime binaries and the narrower circumstances in which their existing
feature evidence can be reused. Acceptance remains pending where indicated.

The comparisons below refer to their named archived candidates. Later normal
build14 repairs, including MI's foreign-sidebar measurement fix, do not make
those older archive bytes current. The [exact repair-chain record](../../output/release-readiness/repair-prefix-equivalence-483-01.json)
and each feature's native follow-up determine whether a particular original
scope remains accepted. A baseline comparison, an opening-only check and a
fresh feature workflow are reported separately; their counts are not added
together as extra executions.

## Modern Industrialization

The [binary comparison](../../output/release-readiness/retained-mi-baseline-build13-01.json)
verified the original staged SHA-256 against the actual preserved runtime jar
on 1.20.1 Fabric and 1.21.1 NeoForge. It then traversed MI's adapter dependencies
inside Compatibility: **14 and 15 classes respectively are byte-identical** to
normal build13. The native MI publisher binaries also match the retained
manifest. The record lists every compared class and external Core contract.

The [original verification](../../output/modern-industrialization-implementation/verification.json)
contains 110 scoped geometry observations per target. Their native component
and complete-cell checks cover variants that use the same machine renderer.
Retained final actions also cover real slot locking/auto-eject changes, Forge
Hammer recipe/output/tool damage, item and fluid pipe settings and persistence,
water-container conversion and expanded tank shape controls. See the exact
limits in the [integration guide](../../compatibility/modern-industrialization.md).

This supports retaining those particular adapter/feature baselines. It does
not establish long production chains or every formed multiblock simulation,
nor turn a newly opened empty energy/fluid panel into a production test.
The final current-artifact publisher run must still show the same publisher,
correct native entry/model, valid layout and slot policy for each advertised
variant. Current Core input, native capture and public-contract acceptance are
separate requirements because Core changed since these retained tests.

## Modern Powah

The [binary comparison](../../output/release-readiness/retained-powah-baseline-build13-01.json)
checks actual preserved runtime jars on 1.21.1 and 26.1.2 NeoForge against their
original staged hashes. **All 16 transitive Compatibility classes on each
target are byte-identical** to normal build13; the native publisher also
matches. The two original journals each contain 125 passing focused checks.

Those journals include face/redstone actions, nondefault clicked-face ownership,
native channels, bound-card acceptance/refusal, item return, fuel generation,
formed reactor controls, native fluid fill/drain and bucket conversion, capacity
upgrade consumption, movement, attachment controls and close/reopen. They also
check that native controls and complete cells retain mapped regions across the
twelve opening routes. The evidence concerns those representative tiers and
states; it does not certify every automation chain or arbitrary modpack.

As with MI, this is retained baseline evidence plus a precise binary comparison.
Fresh matching publisher entry/input and current Core acceptance are required
before a particular coverage row can receive an equivalence disposition. The
comparison itself deliberately says `explicit-acceptance-pending`.

## Tech Reborn

The [five-target retained audit](../../output/release-readiness/retained-techreborn-baseline-build13-02.json)
seals **539 original focused checks**: 22 on 1.20.1 Fabric, 124 on 1.21.1
Fabric and 131 each on 26.1.2, 26.2 and 26.3 Fabric. It verifies each main,
formed-heat and applicable reactor journal against its own actual runtime
subject. It also preserves local copies of those old Compatibility binaries
and hashes their native screenshots. The relevant transitive adapter classes
are unchanged: 15 on 1.20.1 and 19 on each later target.

RebornCore is bundled as a declared nested jar in these exact Tech Reborn
releases. The audit checks its native mod ID/version and nested SHA-256 inside
the hash-verified outer publisher; it does not substitute a separately
downloaded dependency. The initial audit's incorrect assumption about two
top-level files is preserved in
`output/release-readiness/retained-techreborn-baseline-build13-01.failure.json`.

The retained actions include real item/fluid configuration, redstone and
upgrade controls, native pump/detector/output adjustments and server/client
heat on an actually formed blast furnace. The 6.x reactor checks cover fuel
restrictions and its hologram, not reactor energy production. These are
representative integration actions and geometry observations, not a complete
Tech Reborn production-chain test. In particular, the native 6.0.5
`reborncore:padded` recipe-serializer warning remains outside the certified
recipe scope.

This audit establishes retained evidence inputs only. A current coverage row
still requires matching native publisher bytes, appropriate current entry
and input evidence, and acceptance of the changed shared Core/API paths.
Different publisher patches must not inherit acceptance merely because the
menu class has the same name.

The [retained-input hash record](../../output/release-readiness/retained-feature-inputs-build13-01.json)
also reruns the pure MI geometry assertions against all 220 saved observations,
checking each active native cell, widget and reserved component against its
extraction regions and cutouts. It records the complete observation/capture
hashes and retained action-state files. Both 125-check modern Powah journals
and their captures are hashed as well. This is an offline evidence check;
it adds no new live gameplay acceptance.

The [retained subject manifest](../../output/release-readiness/retained-subject-copies-build13-01/manifest.json)
also preserves content-addressed copies of these four original Compatibility
jars inside the local evidence folder. Their bytes were checked against the
same original audit hashes; the cache paths remain recorded. These are older
test subjects for review, not candidate release files and not public downloads.

## Cases that need further work

Create's retained final 1.20.1 Fabric runtime is also available and matches its
recorded artifact hash. Twenty of its twenty-one transitive adapter classes
are identical. The inspected `CreateNativeFrame` bytecode delta changes the
CBC atlas row from 166 to 168, the separately recorded floating-header-line
fix. The comparison disassembly is retained in
`build/release-readiness/create-native-frame-comparison`. Its historical
feature evidence must not receive blanket byte-equivalence acceptance. Fresh
native-feature replays are prepared for all three advertised Create targets;
they remain pending until their actual runtime journals pass.

Curios/Accessories/Aether replacements need explicit API-surface coverage;
absence of their original native Screen is intentional and does not establish
that an upstream interface is unavailable. The new focused boundary runs and
the matching publisher cases retain their exact scopes.

The [current coverage backlog](../../output/release-readiness/coverage-backlog.csv)
continues to list unresolved rows. No row is closed merely by this document or
by class-name, screenshot or filename similarity. The independent final
review must be able to inspect the original feature, exact binary comparison,
current shared-path checks and matching target/publisher disposition together.
