# 26.3 controller and Extended compatibility verification

This pass is limited to Minecraft 26.3 Fabric and NeoForge on
`controllify-jar-test`. It exercises the three separate production JARs together:
Core, Extended and the Controlify companion. The upstream mods are unmodified
published files. Their immutable versions, filenames and SHA-512 hashes are in
[the fixture manifest](mod-fixtures-26.3.json).

## What the checks exercise

The full controller suite covers its 11 common feature areas and 43 additional
26.3 areas: native pointer and D-pad navigation, exact transfers and sorting,
window selection and close behavior, tucked gameplay and icons, animations,
crafting/cooking callbacks, live recipe previews and item conservation, recipe
and creative wheels, alphabetical navigation, filters, stack limits, compact
guides and native glyphs, UI sounds/settings, and creative search keyboard input
capture and release. Supplemental `wheel-polish`, `wheel-stability` and `crafting-qol` runs cover
the more recent performance, filtering, presentation and crafting cleanup changes.

The optional-mod profiles use **JEI and REI separately** on each loader. Both
include Tom's Storage. NeoForge also includes AE2 with GuideME and Sophisticated
Core, Storage and Backpacks. Fabric includes Mod Menu. The exact profiles include
each mod's required runtime dependencies.

Controller-specific native checks include:

- Tom's storage/crafting terminals and connector link configuration: D-pad targets,
  text-field selection, real keyboard editing and return to the workspace.
- JEI/REI tabs, catalog entries, actual recipe ingredients, search filtering and
  virtual recipe clicks without mutation of the player's real inventory.
- Sophisticated chests, barrels and limited barrels, native control targets,
  chest/barrel/backpack search fields and the held backpack's source-item lock.
- AE2 chest and cell workbench controls. A real workbench ghost filter copies a
  carried stack without consuming it; server counts verify conservation afterward.
- A powered AE2 ME network with real storage cells and stored items: adjacent
  virtual slots, one-row D-pad scrolling, analog right-stick scrolling, search
  keyboard input, withdrawal and deposit with exact server item counts.
- An unfamiliar public-API view with changing geometry, tabs, a virtual entry,
  edge/analog scrolling, Unicode typing, exclusive keyboard input and restored
  controller behavior. The companion contains no mod-specific branch for this view.

## Implementation findings

Extended's 26.3 sources now include the available REI and Sophisticated adapters.
The Sophisticated opening-data decoder consumes the current linked-storage flag
and optional payload while retaining its trailing-data validation. Native pointer
events use 26.3's `InputConstants` values.

Core consumes committed API `CONTROL` and `SLOT` regions as pointer targets.
Virtual entries retain their native click handler and never acquire ordinary
inventory-slot authority. API controls keep their actual centers instead of being
merged into 20-pixel cells; vanilla's existing authored navigation is preserved.
The AE2 adapter publishes native repository entries as well as menu slots.
JEI ingredient targets use the native hit test rather than decorative artwork
extents, with cached geometry to avoid rescanning each frame.

REI's 26.3 graphics copy constructor shares Minecraft's render queue but drops
the parent pose and scissor. The adapter carries both into REI's graphics object
for entries, category icons, recipes and tag trees. Native checks compare the
actual queued item positions, scale and clip at identity and transformed poses;
they match geometry independently of render-queue traversal order. Screenshots
are also inspected. Browser presentation bounds now include its protruding tabs,
history/options controls and station sidebar, so these controls fit beside the
other pane and remain reachable.

Definitions publish native scroll viewports and text-field bounds through optional
public API queries. Native wheel handlers still perform scrolling; AE2's wheel
delta is scaled so a D-pad edge press advances one row. Editor focus and input
remain owned by the integration. Controlify's automatic `EditBox` hook is deferred
inside the workspace so it cannot install an overlay before the native field
receives focus, or create a second overlay while the field is refocused. The
workspace keyboard uses Controlify's layout and captures input until close and
neutral release. Retained search focus cannot turn an item click into a keyboard
action. See [the API contract](../../docs/markdown/desktop_window_api.md#controller-navigation-and-editors).

## Reproduce

The native runs used Microsoft OpenJDK 25.0.2, a disposable integrated-server
world and a synthetic driver installed in the actual Controlify manager. The
launcher reserves 3 GiB and limits background workers to two. Production code
loads from the staged JARs; QA is a separate development source set/JAR. Report
verification checks the exact loaded releases and pinned upstream files.

```powershell
python controlify/functional-tests/prepare-mod-fixtures.py --loader all --browser all
foreach ($loader in @('fabric','neoforge')) {
    foreach ($browser in @('jei','rei')) {
        .\gradlew.bat -I controlify/functional-tests/controlify-qa.init.gradle `
            ":controlify:26.3:${loader}:runPackagedControlifyQa" `
            -PcontrolifyQaScope=mod-compat -PcontrolifyQaExtension=true `
            "-PcontrolifyQaFixtures=$browser" -PcontrolifyQaJvmVendor=Microsoft `
            --no-parallel --max-workers=2 --console=plain
        if ($LASTEXITCODE) { throw 'Controller compatibility profile failed' }
    }
    foreach ($scope in @('all','wheel-polish','wheel-stability','crafting-qol')) {
        .\gradlew.bat -I controlify/functional-tests/controlify-qa.init.gradle `
            ":controlify:26.3:${loader}:runPackagedControlifyQa" `
            "-PcontrolifyQaScope=$scope" -PcontrolifyQaExtension=true `
            -PcontrolifyQaJvmVendor=Microsoft --no-parallel --max-workers=2 --console=plain
        if ($LASTEXITCODE) { throw 'Controller feature profile failed' }
    }
}
```

Each profile has its own retained runtime under the loader's
`build/runtime-smoke/packaged-controlify-<report-name>` and evidence under
`build/controlify-qa/<report-name>`. A failed assertion fails Gradle even when the
game exits normally. `tools/verify-controlify-compat-runtime.py --require-matrix`
requires both full loader runs, all recent feature scopes on both loaders and all four browser profiles, validates required
semantic checks, screenshots, native code sources, original dependency hashes,
and their equality with the final collected production JARs.

The [native input isolation note](26.3-native-input-isolation.md) describes the
bounded QA-only host mouse-motion filter. It does not replace native controller
input or change shipped mouse/controller behavior. Runtime JSON includes that
policy and the recorded events.

## Availability and limits

The official Modrinth 26.3 version queries found JEI 31.16.0.84 and REI 26.3.824
for both loaders; Tom's Storage 26.3-2.12.2-fabric and 26.3-2.12.3 for their
respective loaders; AE2 26.3.1-alpha and GuideME 26.3.4-alpha for NeoForge;
Sophisticated Core 26.3-1.5.14.2411, Backpacks 26.3-3.26.13.2209 and Storage
26.3-1.5.123.2187 for NeoForge. The checked official 26.3 EMI version list was
empty, so **EMI is unverified on 26.3**. AE2 and Sophisticated were not available
as 26.3 Fabric fixtures. Availability was checked on 2026-10-19 UTC through the
[official version API](https://docs.modrinth.com/api/operations/getprojectversions/);
the fixture manifest retains the selected official file URLs and hashes.

These are automated game/runtime tests with representative native menus and
explicit feature assertions. Physical controllers, a separate multiplayer server,
every mod version and every possible upgrade/configuration combination were not
tested. An unregistered mod screen still needs an API integration; the companion
adapts dynamically to the controls, slots, scrolling and editor information that
the integration exposes. No merge is part of this verification.
