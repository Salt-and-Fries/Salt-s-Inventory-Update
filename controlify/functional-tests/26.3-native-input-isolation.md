# Native controller test input isolation

The 26.3 gameplay harness uses a disposable world and an installed synthetic Controlify driver. While the unfinished run owns that current controller and its world/player is loaded, the QA mod intercepts only SDL mouse-motion delivery from `SDLEventHandler.pollEvents`, including the gaps between scheduled stages. It forwards those events before installation and after completion. Keys, mouse buttons and wheel events retain their native routes.

Controlify's controller motion and `snapToPoint` call the native `MouseHandler.onMove` directly; they do not pass through the intercepted SDL queue. Native controller bindings, pointer dispatch, rendering, and the exact cursor enabled/position assertions remain unchanged. This isolation is implemented only in the QA mod and does not appear in distributed Core or controller companion jars.

The runtime report records the policy, exact scope, total blocked events, and at most 64 recent event metadata records, including scenario, SDL device/window identifiers, timestamp, coordinates and relative motion. The verifier validates this evidence when present and reports unfiltered earlier successful runs as isolation not applied. A zero event count is valid when the desktop produces no competing motion.

This fixture was added after a native lifecycle trace showed SDL motion invoking Controlify's mixed-input `showCursorTemporarily`, which warps the desktop cursor and rebases virtual cursor coordinates. It does not change production mouse/controller switching behavior.
